# Dagger app ↔ rover contract

The one interface between the operator app (Kotlin, `DaggerGCS`) and the rover
gateway (Python, `dagger_ros2_ws`). Both repositories use this folder; it is
meant to become its own repository, included in both as a git submodule.

| Path | What it is |
|---|---|
| `dagger/api.proto` | **The schema.** Every message on the wire. Read its header for the seven rules. |
| `vectors/*.txtpb` | Recorded messages, one `Envelope` each, written by hand and commented. |
| `vectors/*.bin` | Their exact encoding. Both sides must decode each to the same thing and encode it back to the same bytes. |
| `make_vectors.py` | Turns `.txtpb` into `.bin`; `--check` fails if any are stale. |
| `contract_test.py` | The behaviour half: plays the app against any rover over a real WebSocket. |
| `pyload.py` | Compiles the schema for Python on the fly, so nothing generated is committed. |

## The contract tests

The Phase 1 exit test (`docs/handoff.md` section 15 in DaggerGCS) is that the
fake rover and the real gateway **both pass these, unchanged**.

**Bytes** — after any change to the schema or the vectors:

```
python make_vectors.py --check        # Python reference: every .bin up to date
```

The app checks the same files from Kotlin (`./gradlew.bat :protocol:test` in
DaggerGCS). The gateway should check them from its own generated Python code:
decode each `.bin`, compare with the `.txtpb`, re-encode
(`SerializeToString(deterministic=True)`), compare bytes.

**Behaviour** — against a running rover:

```
python contract_test.py --url ws://127.0.0.1:8082/api
python contract_test.py --url ws://192.168.144.100:<port>/api --allow-real-rover
```

It sends only `Hello`, `Heartbeat` and `STOP`, and never assumes what the
rover is doing, so it holds for any **parked** rover. Because it sends STOP, an
address that is not on this PC needs `--allow-real-rover`: use it only with the
rover parked and someone holding the RC transmitter.

Needs Python 3 with `grpcio-tools`, `protobuf` and `tornado`. On the Jetson,
apt's `python3-protobuf` and `python3-tornado` (6.1, already installed for the
follow page) cover the runtime; `grpcio-tools` is only needed for `protoc`.

## Changing the schema

1. Only **add** fields. Never renumber, never reuse a number, never change a
   type. Retired numbers go in `reserved`.
2. Add or update a vector in `vectors/` for anything new, then
   `python make_vectors.py`.
3. Run both halves of the tests on both sides before relying on it.
4. Adding a field does not change `ProtocolVersion`. Changing what an existing
   field *means* does.

Kotlin is generated by **Wire** (Square). Wire packs repeated enums only when
told to, so repeated scalar fields carry an explicit `[packed = true]` to keep
the bytes identical across both sides.
